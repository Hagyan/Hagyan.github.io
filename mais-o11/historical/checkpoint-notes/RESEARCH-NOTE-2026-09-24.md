# MAIS-O11 PA-bin parser checkpoint (24 September 2026)

The new `CompactParser.lean` connects the earlier polynomial trace-existence theorem to the actual serialized PA-bin definition prelude and proof-record bytes. The primary certified statement is `MAISO11.Wire.compiled_trace_whole`. For every source grammar `g`, it supplies a bounded sequence `fs` whose combined bytes `definitionPrelude (compile g) ++ fs.wire` are accepted by `decodeWhole`; decoding returns precisely `List.ofFn (dictionary (compile g))` and `fs`. The statement also carries `fs.valid (dictionary (compile g))` and the earlier polynomial upper bound on total characters. The theorem is about existence of a mathematical witness; the previous trace constructor uses noncomputable proof choices and is not a standalone exporting program.

The executable parser handles self-delimiting binary numerals and references, closed terms, formulas with quantifier levels, fresh sequential definitions, back references to already defined registers, axiom and MP record syntax, and the expected record count. Accepted record bytes reserialize identically, and generated records round-trip. Generated source and packed definitions expand to exactly the dictionary used in the existing proof validity theorem. A grammar mismatch discovered here was fixed by making the compact unary D/E serialization parenthesized in `CompactWire.lean`.

**Precise remaining gap:** `decodeWhole` validates syntax, freshness, indexing, and record serialization. `fs.valid` is a separately proved proposition. The parser does not yet compute and decide whether an arbitrary decoded axiom record belongs to the four restricted Enderton axiom families, nor whether each MP record is a valid application. A byte-level executable *proof checker* with a soundness theorem, followed by completeness for the generated trace, is the next step. Nor is a PA-internalized polynomial-time verification/Bew proof established. MAIS-O11 part 1 and part 2 remain unresolved; this result is a certified parser/serialization bridge, not a witness of Löb shortening.

To verify on macOS with Lean 4.19.0 installed through elan, in the unpacked directory run `lake build` and then `lake env lean ParserDemo.lean`. If elan reports a toolchain mismatch, use `elan toolchain install leanprover/lean4:v4.19.0` and retry. No Mathlib dependency is needed.
